# 스팟 이동 경로 — 지도에 길을 잇는 방법

> **상태:** 조사·정책 (2026-08-19 · `v0.4.9-mvp`). **구현하지 않음.**  
> **필수:** 아래 **§0 가능한 방향**을 먼저 읽는다. 지도·경로 작업은 이 절을 따르지 않으면 착수하지 않는다.  
> **증상:** 레그에서 도보를 골라도 지도 선이 자동차 도로를 따른다.  
> **관련:** [`src/lib/directions.ts`](../src/lib/directions.ts) · [`/api/directions`](../src/app/api/directions/route.ts) · [`RouteMap.tsx`](../src/components/RouteMap.tsx) · 웹 가이드 [`/deliverables/development#routing-next`](https://course-sns.vercel.app/deliverables/development#routing-next)

타일은 지역에 따라 가른다. **국내는 네이버**, **해외는 구글**. 문제는 타일만이 아니라 **스팟과 스팟 사이 선(폴리라인) 좌표를 어디서 받느냐**다.

---

## 0. 가능한 방향 (다음 구현 시) — **필수**

지도·레그·Directions를 만지기 **전에** 이 절을 읽는다. 제품은 **국내 전용이 아니다.**

### 지역 전제 (고정)

| 지역 | 지도 타일 | 스팟 사이 경로 | 수단 |
|------|-----------|----------------|------|
| **국내** | 네이버 Maps JS v3 | 아래 A–E (TMAP / ODsay 등) | 도보·자전거·자동차·버스·지하철·기차 |
| **해외** | **구글 지도** | **구글 Directions / Routes** | **모든 스팟 사이 이동 경로** — 도보·자전거·자동차·택시·버스·지하철·기차 |

해외에서는 구글이 타일과 길찾기를 같이 맡는다. 스팟 사이를 점선으로만 잇거나 자동차 도로만 그리지 않는다. 선택한 이동 수단의 실제 경로를 그린다.

국내는 지도 데이터·길찾기 품질 때문에 네이버를 유지한다. 국내 구글 지도는 도로·주소가 약하거나 제한되는 경우가 있어 **국내 타일을 구글로 바꾸지 않는다.**

### 국내 — 다음 구현 우선순위

**A. TMAP 키만 넣기**  
도보(지금 코드에선 자전거도)가 보행 경로로 바뀐다. `getWalkingPath`가 이미 있다. 지하철·기차는 그대로다. **지금 증상(도보=차도)만 없애는 최소 수단.**

**B. TMAP 보행 + TMAP Transit** (`POST /transit/routes`)  
공급자 하나. 도보·버스·지하철·기차. 자전거는 여전히 보행 근사. 구간마다 후보가 여러 개라 첫 결과를 쓸지, 고르게 할지를 정해야 한다.

**C. TMAP 보행 + ODsay 대중교통**  
`searchPubTransPathT` + `loadLane`. 지하철·버스 **실제 노선 모양**을 네이버 지도에 그리기 쉽다. 공식 가이드에 네이버 폴리라인 예시가 있다. 키는 두 개.

**D. 카카오 모빌리티 제휴**  
도보·자전거·대중교통을 한 세트로 맞출 수 있다. 계약 전에는 불가.

**E. 대중교통은 도로로 그리지 않기**  
키를 안 넣을 거면 지하철·기차는 **점선 커넥터**가 정직하다. 기차에 driving을 쓰는 지금이 더 어색하다.

국내 우선: 지금 증상 → **A**, 노선까지 → **B 또는 C**.

### 해외 — 구글 (필수 방향)

구현 시 `directions.ts`(또는 동등 레이어)가 **지역으로 공급자를 가른다.**

- **타일:** Maps JavaScript API  
- **경로:** Directions API 또는 Routes API  
- **모드:** `WALK` · `BICYCLE` · `DRIVE` · `TRANSIT`(버스·지하철·기차·철도)  
- **범위:** 코스의 **모든 연속 스팟 쌍**. 수단이 있는 레그는 해당 모드로 선을 받는다. 빠지는 구간 없이.

키·빌링·사용량 제한은 구글 Cloud에서 관리. 국내 키(네이버·TMAP)와 **분리**한다.

### 하지 않는 것

- 국내 타일을 카카오·구글로 교체  
- 해외 코스를 네이버/TMAP으로만 그리기  
- 해외 스팟 사이를 커넥터만으로 남기기  
- 네이버에 도보 API가 생기길 기다리기

## 1. 왜 도보인데 자동차 도로인가 (국내 현재)

네이버 Cloud **Directions 5 / 15는 자동차 길찾기만** 제공한다. 도보·자전거·대중교통 엔드포인트가 없다.

이 앱의 실제 분기 (`getLegPath`) — **국내만**:

| 수단 | 지금 동작 |
|------|-----------|
| 자가용·택시 | 네이버 Directions `driving` |
| 버스·기차 | 마찬가지로 **driving** (도로) |
| 도보·자전거 | TMAP 보행자 API → **`TMAP_APP_KEY` 없으면 네이버 driving으로 폴백** |
| 지하철 | 경로 API 없음. 점선 커넥터만 |

운영상 `TMAP_APP_KEY`는 **미설정(⬜)** 이다. 그래서 도보를 눌러도 자동차 도로가 그려진다. 네이버가 도보 선을 주는 게 아니라, **키가 없어 driving으로 떨어지는 것**이다.

좌표계는 모두 WGS84라, 네이버 타일 위에 TMAP·ODsay 선을 올리는 것은 가능하다. 이미 그 구조다 (`RouteMap`이 `path` 좌표를 폴리라인으로 그림).

## 2. 수단별로 길을 이을 수 있는지

국내 공급자 비교. 해외는 §0 구글.

| 수단 | 네이버 | TMAP (공개) | 카카오 모빌리티 | ODsay | 구글 (해외) |
|------|--------|-------------|-----------------|-------|-------------|
| 도보 | ❌ driving만 | ✅ 보행자 경로. **코드 있음** (`getWalkingPath`) | ✅ 도보 API · **제휴** | — | ✅ `WALK` |
| 자전거 | ❌ | ❌ 전용 라우터 없음. 지금은 보행 API 근사 | ✅ 자전거 도로 옵션 · **제휴** | — | ✅ `BICYCLE` |
| 자가용·택시 | ✅ | ✅ 자동차 | ✅ | — | ✅ `DRIVE` |
| 버스 | ❌ (driving 위장) | ✅ Transit | ✅ 통합 길찾기 · **제휴** | ✅ 길찾기+노선 그래픽 | ✅ `TRANSIT` |
| 지하철 | ❌ 커넥터 | ✅ Transit | ✅ · **제휴** | ✅ `loadLane` 선형 | ✅ `TRANSIT` |
| 기차 | ❌ (driving 위장) | ✅ Transit `pathType` 5 | △ | ✅ 시외·철도 | ✅ `TRANSIT` (rail) |

대중교통은 점 A→B 한 줄이 아니다. **걸어가기 → 탑승 → 환승 → 걷기**다. 구글 Transit도 구간을 나눠 준다. 그 좌표를 스팟 사이 선에 이어 붙인다.

## 3. 참고 엔드포인트

- 네이버 driving: `https://maps.apigw.ntruss.com/map-direction/v1/driving` (자동차만, 국내)
- TMAP 보행: `https://apis.openapi.sk.com/tmap/routes/pedestrian?version=1`
- TMAP 대중교통: `https://apis.openapi.sk.com/transit/routes`
- ODsay: `searchPubTransPathT`, `loadLane` (lab.odsay.com)
- 구글 (해외): Maps JavaScript API · Directions API 또는 Routes API (`WALK` / `BICYCLE` / `DRIVE` / `TRANSIT`)

## 4. 다음에 손댈 때

1. **먼저 §0을 다시 읽는다.** 국내/해외를 한 공급자로 합치지 않는다.
2. 국내 도보 차도 위장 → **A** (Vercel `TMAP_APP_KEY`).
3. 국내 지하철·버스·기차 노선 → **B 또는 C**.
4. 국내 자전거 전용 도로 → **D** 또는 보행 근사 유지.
5. 해외 → 구글 타일 + 전 수단 경로. 모든 스팟 쌍. 키는 네이버/TMAP과 분리.
6. 국내 구현 시 타일은 네이버, 선만 다른 API. `directions.ts`에 지역 분기를 둔다.
